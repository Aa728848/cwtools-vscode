# Agent Note: Release v2.38.0 —— 全局舰船设计工作台与 Agent 管理器 GUI 预览

Status: implemented

## Problem

自 `v2.37.0`（2026-11-15）发布以来，主分支已有 1 个未发布提交（Agent 管理器 GUI 预览），工作区另有一项完成验收但尚未提交的大型特性：全局舰船设计可视化工作台。两者都新增了用户可见能力，需要按可追溯的扩展版本发布。

## Decision

1. **版本定级（Minor `2.38.0`）**：两项均为新增特性且不移除既有能力，按 SemVer 与仓库惯例升级次版本；根目录 `package.json` 与 `release/package.json` 的 `version` 同步从 `2.37.0` 升到 `2.38.0`（2026-11-21）。`package-lock.json` 沿用以往发布惯例不随版本号改动。
2. **更新日志合并**：开发期间 `[Unreleased]` 中按迭代追加了十余条舰船工作台条目，其中多条描述的是已被后续迭代取代的中间状态（如中央“填满空槽”投放区、左下设计树）。发布时合并为一条描述最终行为的双语条目，并补上此前漏记的 Agent 管理器 GUI 预览条目；设计取舍仍归属各自 Owning Note：[2026-11-20-global-ship-design-workbench.md](../feature/2026-11-20-global-ship-design-workbench.md)、[2026-11-17-agent-manager-gui-development-preview.md](../feature/2026-11-17-agent-manager-gui-development-preview.md)。
3. **发布前国际化检查**：命令标题三份 NLS 同步；Webview 文案全部双语。检查发现扩展端仍有纯英文的用户可见文本（操作失败提示、草稿生成说明、填充结果、外部修改冲突、切换确认与“仅限工作区”警告），同一命令注册区里 GUI/恒星系/实体/粒子预览与舰船工作台的“无活动编辑器 / 文件类型不符”提示也只有英文；本次一并改为通过 `panelI18n.localize` 随显示语言输出，细节见舰船工作台 Owning Note 的国际化段落。
4. **发布方式沿用 CI 单点交付**：与 [2026-11-15-release-v2.37.0.md](2026-11-15-release-v2.37.0.md) 一致，本地只做版本、更新日志、文档生成与门禁预检，不执行 `package.ps1`；推送 `v2.38.0` 标签后由 `.github/workflows/release.yml` 构建全平台 VSIX、发布市场并创建 GitHub Release。
5. **工作区边界**：`submodules/cwtools-stellaris-config` 内未提交的规则同步改动及由其生成的 `release/rules/stellaris-rules.zip` 不纳入本次发布，CI 按标签检出已提交的子模块指针与压缩包。

## Alternatives considered

- **补丁版本 `2.37.1`**：不采纳。两项都是新增的用户可见特性，补丁号无法表达能力边界的变化。
- **保留逐次迭代的更新日志条目**：不采纳。中间状态的条目会误导用户以为存在已删除的界面与交互。
- **把未提交的规则改动一起发布**：不采纳。规则同步是独立迭代，未提交状态无法复现，混入会让发布产物与仓库记录不一致。

## Consequences

- 用户侧：新增舰船设计工作台（命令“打开舰船设计工作台”）与管理器 GUI 预览页；中英文界面随 VS Code 显示语言切换。
- 验证：舰船单元测试、全量单元测试（已知的 Shader 合同 `shader_files` 49/50 失败源自子模块未提交的规则改动，与本次发布无关）、编译、文档生成、发布门禁与 `git diff --check` 均在发布前执行。
- 回退路径：CI 失败时可在 Actions 页面用已有标签重跑；取消市场发布开关只重建 VSIX 与 Release；本地 `package.ps1 -Publish` 仍可作为后备。
