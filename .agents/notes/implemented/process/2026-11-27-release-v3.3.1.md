# Agent Note: 发布 v3.3.1（项目知识库保存写入优化）

Status: implemented

## Problem

v3.3.0 之后的一批改动修复了项目知识库在每次手动保存时产生无谓增量写库的问题：watcher 之前只按路径记录事件，原样保存也会进入 SQLite 增量导出，并额外提交一次统计元数据事务。该改动落在 `cwtools-shared`（`init.ts` 的 unchanged 复用）与主仓 F# 导出，因此共享包及其下游都要重新发版，扩展也需重新打包才能带上新逻辑。

## Decision

- 主仓版本 `3.3.0` → `3.3.1`（patch）：属于同一功能的性能与写盘优化，无新公开工具或破坏性契约变化。`package.json` 与 `release/package.json` 同步。
- npm 按依赖顺序发布：`cwtools-shared` 0.6.0 → 0.7.0（新增 `unchanged` 语义）、`cwtools-node` 0.4.1 → 0.4.2、`cwtools-mcp` 0.6.1 → 0.6.2；node 与 mcp 依赖同步钉到 `cwtools-shared 0.7.0`。
- `dsh-cwtool` 0.3.3 → 0.4.0，依赖钉到 `cwtools-shared 0.7.0` / `cwtools-node 0.4.2`，并在 `pnpm-workspace.yaml` 的 `minimumReleaseAgeExclude` 登记新版本。
- `release/package.json` 运行时依赖闭包同步更新为 `cwtools-shared 0.7.0` / `cwtools-node 0.4.2`，确保打包内置版本等于 npm latest。
- `submodules/cwtools` 与 `submodules/cwtools-stellaris-config` 本次无代码改动，不发版，仅随根仓库指针保留既有提交。

## Consequences

- npm 实际生效版本：`cwtools-shared@0.7.0`、`cwtools-node@0.4.2`、`cwtools-mcp@0.6.2`、`dsh-cwtools@0.4.0`；四个包现均为对应 npm latest。
- 扩展 3.3.1 打包后内置上述版本，用户升级即可获得保存去抖、内容哈希去重与知识事实短路三层优化。
- 已知限制（沿用 v3.3.0 的既有约束）：升级后每个文件的首次增量保存仍会建立一次事实指纹基线；之后同内容或无语义变化的保存才会完全跳过写库。
- 验证：`cwtools-shared` 152 项契约、`cwtools-node`/`cwtools-mcp` 契约、`dsh-cwtool` `pnpm build` 与 140 项测试、主仓 `build:docs`/`compile`/`check:release` 均通过。
