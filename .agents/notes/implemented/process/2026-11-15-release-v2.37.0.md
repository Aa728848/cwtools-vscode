# Agent Note: Release v2.37.0 —— 移除扩展自建自动更新并改为标签驱动的市场发布

Status: implemented

## Problem

自 `v2.36.0`（2026-11-10）发布以来，主分支合入了 10 个提交，交付面集中在两件互为因果的事：

1. **扩展自建的自动更新被整体移除**：`client/extension/updateChecker.ts` 每次激活都会请求 GitHub `releases/latest`，发现新版本后下载 VSIX 并调用 VS Code CLI 安装。这条链路绕开市场，在网络受限环境下要付出查询 5 秒、下载 10 秒的超时代价，还要维护跨平台 CLI 探测与 `globalState` 版本状态，与市场自身的升级判断构成两套真相。扩展本身已发布到 VS Code 市场，检查更新与安装早已由 VS Code 负责。
2. **发布流程改为标签驱动的 CI**：此前发版是手工链路（本地 `package.ps1` 打包 → `build/Program.fs` 交互式 PAT 发市场 → `gh release create`），三者分散且容易只做一半；而认证依赖的 Azure DevOps 全局 PAT 将于 2026-12-01 退役。

两者都改写用户可见行为（下线一个设置项、改变升级路径）与交付流程，必须按可追溯的扩展版本发布。

## Decision

1. **版本定级（Minor `2.37.0`）**：
   依据仓库既有惯例——用户可见能力下线以次版本交付（参见 [2026-11-07-release-v2.35.0.md](2026-11-07-release-v2.35.0.md)、[2026-10-22-release-v2.33.0.md](2026-10-22-release-v2.33.0.md)），将根目录 `package.json` 与 `release/package.json` 的 `version` 从 `2.36.0` 升级为 `2.37.0`（2026-11-15）。
2. **更新日志与技术决策归属**：
   在 `release/CHANGELOG.md` 顶部新增 `## [2.37.0] - 2026-11-15` 双语条目，分「移除扩展自建自动更新」「标签驱动的市场发布 CI」「CI 恢复绿灯」三节。设计取舍归属既有 Owning Note [2026-11-15-remove-extension-self-updater-and-rely-on-marketplace-updates.md](2026-11-15-remove-extension-self-updater-and-rely-on-marketplace-updates.md) 与 [2026-11-15-release-ci-marketplace-trusted-publishing.md](2026-11-15-release-ci-marketplace-trusted-publishing.md)，本篇只记录发布流程决策。
3. **发布方式改为 CI 单点交付**：
   本次不再在本地执行 `package.ps1`，也不手动 `gh release create`；推送 `v2.37.0` 标签后由 `.github/workflows/release.yml` 在 Windows runner 上构建全平台 VSIX、跑发布门禁、通过 Trusted Publishing（OIDC）发布到市场、留档产物并创建 GitHub Release。本地只做版本与更新日志同步、文档生成与发布门禁预检。
4. **工作区边界**：
   工作区中 `submodules/cwtools-stellaris-config` 存在未提交的规则同步改动（`abi-audit.json` 等），本次发布不包含它；CI 按标签检出，打包使用的是该子模块已提交的指针，因此发布产物不会被本地未提交状态污染。

## Alternatives considered

- **升级为补丁版本 `2.36.1`**：
  不采纳。移除了一个用户可见设置项并改变升级路径，属于用户可见行为变化，补丁号无法表达这一边界。
- **升级为破坏性大版本 `3.0.0`**：
  不采纳。扩展的核心能力（语言服务、可视化编辑器、AI 工作区、Workshop 上传、MCP 桥接）完全保留，移除的只是一条与市场重复的自更新链路；大版本号会制造破坏性预期。
- **本次仍按旧 SOP 在本地打包并手动发市场**：
  不采纳。CI 发布链路已在 v2.36.0 的两次冒烟运行中验证过（OIDC 换取凭据、门禁、产物留档、Release 更新），继续手工发版会让新链路永远得不到真实版本的验证。
- **把子模块未提交的规则改动一并发布**：
  不采纳。规则同步属于独立的规则迭代，未提交状态无法复现，混入扩展版本会让发布产物与仓库记录不一致。

## Consequences

- 用户侧：升级交给市场自动更新；从 Releases 安装 VSIX 的用户需要手动重新下载新版。设置项 `stellarisLanguageServices.checkForUpdates` 消失，遗留值由 VS Code 忽略。
- 交付侧：`v2.37.0` 标签是本仓库第一条走 CI 发布链路正式发布的版本，产物同时出现在市场与 GitHub Release，VSIX 另存为工作流产物 14 天。
- 回退路径：若 CI 发布失败，可在 Actions 页面手动运行工作流并填写已有标签；关闭市场发布开关则只重建 VSIX 与 Release；本地 `package.ps1 -Publish` 仍可用。
