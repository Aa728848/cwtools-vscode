# Agent Note: Release v2.25.0 for Subscription Account Pools

Status: implemented

## Problem

自 `v2.24.0`（2026-09-30）以来共 22 个提交、120 个文件、+19083/-293。改动高度集中在 AI 订阅账号体系，与上一版（CW279–CW289 引擎事实诊断）几乎不重叠。核心问题：

1. **每条订阅线路只能用一个账号。** 凭据一旦 401 / 429 就只能干等冷却，没有轮换、没有故障转移。登录按钮在已有账号后被隐藏，第二个账号根本无从添加——而恰好只有 WorkBuddy 与 MiniMax 保留着按钮，也恰好只有它们能加第二个账号。
2. **账号身份不可靠。** WorkBuddy 依赖一个尽力而为的账号接口拿不到就退化成显示名，把同一账号存成两行；MiniMax 托管凭据不带身份键，重复登录产生重复行，且已经写成两行的旧文档不会被修复。
3. **配额完全没有渲染。** WorkBuddy 的配额元素存在却无人写入，任何池行都不带用量。
4. **各线路在传输层细节上大量不一致**，部分不一致就是硬失败：Claude 自适应思考形态从不携带 `block_binding`、Command Code 从不发 `max_completion_tokens`、Kimi 的 2 MB 请求体保护根本不存在、MiniMax 无 401 刷新重放、WorkBuddy 无 usage trailer。
5. **额度与配额等 UI 信号缺席**，用户在设置页看不到任何额度信息。

第 1–4 组包含**新增的用户可见功能**（三到六条新订阅线路、多账号池、每账号配额、WorkBuddy 每日签到），依据 SemVer 应升级次版本。

## Decision

1. **版本号升级（Minor）**：根目录 `package.json` 与 `release/package.json` 统一升级为 `2.25.0`。
2. **更新日志编写**：在 `release/CHANGELOG.md` 顶部新增 `## [2.25.0] - 2026-10-06` 区块，按既有双语格式分四组：订阅账号池与供应商扩展；账号身份、轮换与登录可达性修复；请求健壮性与参考实现对齐；规则同步工具与内置规则。
3. **单源文档与门禁**：运行 `npm run build:docs`、`npm run compile` 与 `npm run check:release -- --skip-compile --skip-test`。
4. **跨平台通用 VSIX 打包**：执行根目录 `package.ps1`。
5. **Git 与 GitHub 发布**：提交、打 `v2.25.0` 标签、推送并通过 GitHub CLI 创建 Release 挂载 VSIX。

## Alternatives considered

- **升级为补丁版本 `2.24.1`**：不采纳。本版新增 claude-subscription、workbuddy-subscription、minimax-code 三条订阅线路与多账号池内核、每账号配额、WorkBuddy 每日签到，属于新特性而非缺陷修复。
- **把本次改动按线路拆成多个次版本**：不采纳。这些提交共享同一个账号池内核与同一份失败分类，拆开发布会把中间状态交付给用户——例如「有池无身份键」「有轮换无配额」，那样的中间态对用户没有价值。
- **让配额参与路由决策（例如额度耗尽即冷却）**：不采纳。配额是呈现，不是路由状态；读取失败只让该行没有数字，而不是停用账号。
- **为 MCP 服务器内联可写能力以便配额查询**：不采纳，`submodules/cwtools-mcp` 的只读契约不因本次发版放宽。
- **把「账号池区块不可见」按 provider 逐个打补丁**：不采纳。四处缺陷（种子只扫桌面凭据、载荷只带已保存 provider、操作作用于已保存 provider、区块渲染在 Codex 提前 return 之后）共享同一个 payload 与渲染结构，按结构修复一次。

## Consequences

- 发布 `v2.25.0` 通用扩展包，覆盖 Windows / Linux / macOS 自包含运行环境。
- 所有订阅线路共享一套账号池内核：顺序 / 轮询 / 粘性调度、429 冷却故障转移、401 强制刷新、吊销停用、幂等入池；登录按钮不再隐藏，第二个账号对所有线路可达。
- 新增 claude-subscription、workbuddy-subscription、minimax-code 三条线路；commandcode、codex-chatgpt、kimi-code-plan 增强。
- 每账号配额在各线路自身行下渲染，仅上屏后按需读取一次并按账号缓存；WorkBuddy 每日签到上线（仅限中国区账号）。
- 图片预算改为按线路计算；Anthropic 缓存断点移到最后一个 user 轮；出站文本清洗 NUL 与孤立代理字符。
- 十二项参考实现对齐硬失败修复，含 `block_binding`、`max_completion_tokens`、Kimi 请求体保护、MiniMax 401 刷新重放、WorkBuddy usage trailer，以及工具名 `+=` 累积的潜在派发失效。
- 规则同步新增作用域契约提取与报告；相对从句、多态作用域、跨行字符串三类误判修复。
- 已知局限：账号池的配额读数来自各服务商参考实现的实测端点，服务端契约变化会让某一行的数字缺席，但不会影响该账号的调度。
- 版本号仅由根 `package.json` 与 `release/package.json` 承载，文档与注释不重复数字。
