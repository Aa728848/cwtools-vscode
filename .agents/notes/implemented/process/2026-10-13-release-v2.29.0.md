# Agent Note: v2.29.0 发布（Agent Skill 体系 / Home 配置 / AI Workflow 移除）

Status: implemented

## Problem

v2.28.0 之后累积了 7 个未发布提交，其中两批是架构级改动：PTC 模式彻底移除（净删约 3000 行）、Agent Skill 体系与 AI Workflow 子系统移除。这些改动此前只写在 `release/CHANGELOG.md` 的 `[Unreleased]` 段（且只覆盖了 PTC 一条），版本号仍停在 2.28.0。

## Decision

### 1. 版本号：2.29.0（次版本）

按 SemVer 判定为次版本而非补丁：新增了 `/skill` 斜杠入口、`save_skill` 模型可见工具、`~/.cwtools` 用户级配置三项用户可见能力，并移除了一个完整子系统。无破坏性 API 变更（历史话题数据全部可读），故不升主版本。

### 2. CHANGELOG：先修复既有损坏，再追加本版

发布前发现 `release/CHANGELOG.md` 已被**破坏**，且不是本次发布引入：

- 提交 `529e8492`（remove PTC mode）把该文件从 2,458 行削到 195 行——**176 个历史版本段落（1.5.0 ~ 2.22.1，约 172 KB）被删除**，只剩 2.23.0 起的 7 段；
- 同一次写入还把 2.24.0 段里一行 2,210 字符的描述**截断成 2,000 字符并插入字面文本 `... (line truncated to 2000 chars)`**。

两处都是工具写入时的产物（长行截断 + 整文件覆写），提交信息只提到「add an Unreleased bilingual CHANGELOG entry」，没有提及删除历史。

处理方式：以 `git show v2.28.0:release/CHANGELOG.md`（该 tag 版本是干净的、且是当前文件的严格超集）为基线恢复全部 182 个历史段落，再在其上追加 `## [2.29.0]` 段。恢复后逐段比对确认：**0 段缺失、0 段内容变化、截断痕迹消失**。

本版新增四组条目（中英双语）：Agent Skill 与 Home 配置、AI Workflow 移除、MCP 0.2.7，以及继承自 `[Unreleased]` 的 PTC 移除。

### 3. 发布范围

- 两处 `package.json`（根与 `release/`）同步升到 2.29.0。
- `cwtools-mcp` 0.2.7 已先行发布并提升根仓库子模块指针（见 `chore(mcp): bump submodule to the 0.2.7 release commit`），本版 VSIX 因此携带更新后的子模块指针。
- 三平台自包含语言服务器与通用 VSIX 由 `package.ps1` 产出。

## Alternatives considered

1. **只追加 2.29.0、不修历史段落**：否决。176 个版本的更新日志是发布资产（Marketplace 与 GitHub Release 都引用它），静默丢失且已被提交固化，越晚恢复越难；而且恢复源（v2.28.0 tag）是干净的超集，恢复是无损的。
2. **用 `git revert 529e8492` 恢复 CHANGELOG**：否决。该提交同时删除了 `quickjs-emscripten` 依赖与大量源码，revert 会连 PTC 移除一起回滚。
3. **升级到 3.0.0**：否决。移除 AI Workflow 不构成对用户可见配置或数据的破坏——历史话题仍可读，`/workflow:*` 命令消失属能力下线而非接口破坏。
4. **把 CHANGELOG 拆成归档文件**（历史段落移到 `docs/CHANGELOG-archive.md`）：否决。当前问题是被误删，不是体积；拆分是另一个决策，不应混进恢复性修复。

## Consequences

- 更新日志恢复到完整 183 段（182 历史 + 1 新版），不再有截断痕迹。
- 用户升级到 2.29.0 后：`/skill` 与 `/skill:<name>` 可用，技能可保存到项目或 `~/.cwtools/skills`，MCP 支持三层配置合并，`/workflow:*` 与 `save_workflow` 消失，自动模式路由不再被 workflow 跳过。
- 遗留项（不在本版范围）：`cwtools-mcp` 的 CI `bundle` job 声明了 `if: startsWith(github.ref, 'refs/tags/v')`，但工作流触发器只有 `push: branches: [main]` 与 `pull_request`，**没有 `tags`**——该 job 永远不会运行，README 承诺的「从 Releases 下载 `cwtools-mcp.cjs`」这条路径从未被验证（实测 `gh release list` 为空）。修法是给 `on:` 加 `tags: ['v*']`。
