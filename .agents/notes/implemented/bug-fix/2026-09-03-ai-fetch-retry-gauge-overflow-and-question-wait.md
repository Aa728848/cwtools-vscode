# Agent Note: AI Fetch Retry, Context Gauge Overflow, and Question Waiting

Status: implemented

## Problem
在 AI 助手运行和 Webview 交互过程中存在三项关键缺陷与稳定性隐患：
1. **网络偶发瞬断中断任务**：与上游模型 API 通信时，瞬时网络故障或 429/5xx 抖动会导致当前任务直接抛错终止，缺乏重试机制。
2. **Context Gauge UI 溢出**：Webview 聊天界面的上下文使用率指示计在上下文接近或突破安全阈值时，样式计算未做边界收敛，导致仪表盘进度条溢出甚至破坏布局。
3. **用户问答超时中断**：模型向用户发起追问（`ask_question`）时，受通用工具调用的默认超时时间约束；若用户思考或编辑回复耗时稍长，即会触发超时失败，打断人机协同。

## Decision
1. **增强 Fetch 弹性重试机制**：
   - 在底层的 HTTP 请求通道中引入针对网络传输异常及瞬时 HTTP 状态码的重试机制，结合退避算法提升对不可靠网络的容错度。
2. **修复 Context Gauge 边界计算**：
   - 对 Token 使用率和进度条比例加入上下限安全约束（clamping），杜绝负值或超过 100% 导致的布局异常。
3. **允许问答交互无限等待**：
   - 特化交互式追问工具的生命周期管理，解绑固定超时限制，使其能够挂起并持续等待用户的主动输入或选择。

## Alternatives considered
- **在各个业务调用点分散实现重试**：
  - *未采纳原因*：分散在各工具或 Agent 中会导致重试逻辑割裂且难以统一调优，集中在网络请求基础设施层处理更为健壮和一致。
- **将问答超时延长至数十分钟**：
  - *未采纳原因*：无论多长的时间阈值，在人机交互场景下都可能遇到用户暂时离开电脑的情况；将交互型挂起视为正常状态比硬编码大超时更合理。

## Consequences
- AI 对网络瞬时抖动的韧性大幅提升，减少了无谓的任务重跑。
- 界面指示计在极端超长上下文中保持优雅显示。
- 修复了用户交互被打断的硬性体验问题，支撑了 2.16.7 版本的正式发布。
