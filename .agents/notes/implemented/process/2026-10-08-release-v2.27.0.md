# Agent Note: 发布 v2.27.0

Status: implemented

## Problem

用户在 2.26.0 引入创意工坊上传后反馈：上传成功但无法排除文件，希望直接复用 git 的忽略文件。经查证 Steam 的内容接口（`ISteamUGC::SetItemContent`）只接受目录且无逐文件过滤参数，`.steamignore` 仅为 SteamPipe ContentBuilder 路径识别，因此过滤必须在扩展侧实现，遂发布 2.27.0 交付该能力。

## Decision

- **版本号**：2.26.0 → 2.27.0（次版本）。依据 SemVer，本次为用户可见的新特性而非补丁修复；且用户明确要求发版，合并同一工作区内的文件清理提交。
- **过滤位置**：扩展侧生成暂存副本，而非寻找 Steam 侧的开关。这是本版本最核心的技术判断——详见 `.agents/notes/implemented/feature/2026-10-07-steam-workshop-upload.md` 中「文件忽略（追加决策）」一节。
- **依赖策略**：`ignore@5.3.2`（MIT、零依赖）此前已作为 globby/eslint 的传递依赖存在于依赖树中，本次提升为直接运行时依赖，并由 package.ps1 4b 步暂存进 release/node_modules。选它而非自研匹配器，是因为 gitignore 语义（否定、目录作用域、`**`）细节繁复，自研等于长期维护一份 bug 集合。
- **随包发布**：延续 2.26.0 已确立的「Extension Host 无 bundler，运行时依赖由 package.ps1 显式暂存」约定，未引入新的打包机制。

## Consequences

- **收益**：Mod 作者无需手工整理文件夹即可上传干净内容；`.git` 不再随包上传。
- **已知边界（发布时未修复，已向用户说明）**：`workshop.useIgnoreFiles=false` 会整体旁路 `stageUploadContent`，此时内建基线（`.git` 等元数据排除）一并失效，Mod 文件夹原样上传。理由是保证「关闭功能 = 回到该功能存在前的行为」；风险是用户可能在不知情下把仓库历史发布到公开工坊。用户已被明确告知并可选择后续修复。
- **未实测项**：`package.ps1` 的 4b 步本次首次携带 `ignore` 执行，`npm run test:unit` 与 `check:release` 不覆盖真实打包；VSIX 中 `release/node_modules/ignore` 的实际落盘由本次打包流程本身验证。
- **测试状态**：workshopIgnore 17 例单测；`npm run test:unit` 2889 例全绿（2.26.0 基线 2872 + 17）。
