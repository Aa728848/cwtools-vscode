# Agent Note: MiMo V2.6 系列供应商目录与定价刷新

Status: implemented

## Problem

小米 MiMo 近期正式发布并开源 MiMo-V2.6 系列 3 款全新模型：`mimo-v2.6-pro`
（旗舰）、`mimo-v2.6-flash`（高频办公）、`mimo-v2.6-pro-ultraspeed`（实时低延迟定制档）。
全系为原生全模态（图像/音频/视频理解），支持深度思考、流式输出、函数调用、
结构化输出与联网搜索，上下文窗口 1M、最大输出 128K。官方同时公告
`mimo-v2.5-pro` 与 `mimo-v2.5` 将于 2026-10-21 10:00（北京时间）正式下线。

按量计费实时 API 价格（人民币 / 百万 tokens）：

| 模型 | 输入（缓存命中） | 输入（缓存未命中） | 输出 |
| --- | --- | --- | --- |
| `mimo-v2.6-pro`（与 V2.5 Pro 同价） | 0.025 | 3.00 | 6.00 |
| `mimo-v2.6-flash`（与 V2.5 同价） | 0.02 | 1.00 | 2.00 |
| `mimo-v2.6-pro-ultraspeed` | 0.25 | 30.00 | 60.00 |

其中 `mimo-v2.6-pro-ultraspeed` 不支持 Batch API，且只按量计费；官方 Token Plan
订阅只覆盖 `mimo-v2.6-pro`、`mimo-v2.6-flash` 与 V2.5 全系模型。三款模型在思考模式下
均不支持自定义 `temperature`/`top_p`（由模型强制为 1.0 / 0.95）。

本仓库 mimo 与 mimo-token-plan 供应商目录此前停留在
`['mimo-v2.5-pro', 'mimo-v2.5']`，默认模型仍是 `mimo-v2.5-pro`；新模型 id 不在
能力表、定价表与思考参数判定中，会退化为「未知模型」处理（视觉能力判定为 false、
成本估算为 0、思考协议无法识别）。

## Decision

- 供应商目录（`providers/models/defaults.ts`）：mimo 默认模型改为
  `mimo-v2.6-pro`，列表为 V2.6 三款并保留过渡期 V2.5 两项；mimo-token-plan
  同步默认模型，列表仅含 `mimo-v2.6-pro`、`mimo-v2.6-flash` 与 V2.5 两项，
  与官方订阅覆盖面一致，不列入 ultraspeed。
- 能力表（`providers/models/capabilities.ts`）：`VISION_CAPABLE_MODELS` 为 V2.6
  三款打开视觉（官方图像理解示例即以 `mimo-v2.6-pro` 传入 image_url）；
  `MODEL_CONTEXT_TOKENS` 补齐三款 1M（1048576）上下文条目。输出预算沿用
  mimo 分支的 131072（官方最大输出 128K），无需改动；
  `isLowCostPrefixCacheModelOrProvider` 的 `mimo-v2` 前缀判定天然覆盖 V2.6。
- 定价表（`providers/models/pricingData.json`）：新增 `mimo-v2.6-pro: [3.00, 6.00]`、
  `mimo-v2.6-flash: [1.00, 2.00]`、`mimo-v2.6-pro-ultraspeed: [30.00, 60.00]`，
  并按长名在前的顺序插入，保证带日期后缀的模型走前缀回退时命中正确档位。
- 缓存折扣（`providers/models/pricing.ts`）：V2.6 Pro 与 Ultraspeed 的
  缓存命中/未命中 = 0.025/3.00、0.25/30.00 ≈ 0.0083；V2.6 Flash = 0.02/1.00 = 0.02，
  与 V2.5 系列同口径。
- 请求整形（`providers.ts`）：`getModelReasoningCapability`（含 mimo 分支与
  网关默认能力判定）与 `DISABLE_THINKING_PARAMS` 中的 `mimo-v2[.]5` 正则放宽为
  `mimo-v2[.](?:5|6)`，继续沿用「思考开关（none/high toggle）+
  `thinking: {type: enabled|disabled}`」协议；`getEnableThinkingParams` 与
  `agentRunner.ts` 的 `mimo-v2` 前缀判定覆盖 V2.6，未改动。
- 回归测试：`providers.test.ts`、`pricing.test.ts`、`providerThinkingParams.test.ts`
  覆盖 V2.6 三款的视觉、上下文、输出预算、供应商目录、价格、缓存折扣与思考参数。

## Alternatives considered

1. **本次直接删除 V2.5 两项**：官方 2026-10-21 才正式下线，过渡期内接口仍接受旧 id，
   立即删除会使已保存会话的模型选择失效，故保留至下线后再清理，与
   [DeepSeek V4.1 Flash 供应商目录与定价刷新](./2026-09-11-deepseek-v4.1-flash-provider-refresh.md)
   处理兼容名的边界一致。
2. **把 `mimo-v2.6-pro-ultraspeed` 也列入 mimo-token-plan**：官方 Token Plan 只覆盖
   Pro/Flash 与 V2.5 全系，ultraspeed 属按量定制档，列入会误导订阅用户选到计费外模型。
3. **同步改写第三方渠道（OpenCode Go / Command Code / TokenRhythm 等）的 mimo 目录**：
   渠道有各自的上架节奏与计费口径，沿用 DeepSeek 刷新确立的边界，本次不越界修改；
   共享能力表与定价表按模型 id 生效，渠道一旦上架 V2.6 即可正确计价与判定能力。
4. **为 V2.6 推断 effort 档位思考参数**：官方只提供思考开关，深度思考模式下还会
   强制 `temperature`/`top_p`，不开放档位，继续按 toggle 处理，不虚构档位。

## Consequences

- 新会话默认使用 `mimo-v2.6-pro`：可接收图片输入，1M 上下文、131072 输出预算与
  0.0083 缓存命中折扣生效；ultraspeed 可选，成本估算按 ¥30/¥60 档显示。
- mimo-token-plan 用户只看到订阅覆盖的 V2.6 Pro/Flash（与 V2.5 兼容项），避免误选。
- 过渡期内 V2.5 两项继续可用；2026-10-21 官方下线后需再做一次目录清理，同步移除
  能力表、定价表与请求整形正则中的 V2.5 专属条目（或转为兼容匹配并记录原因）。
