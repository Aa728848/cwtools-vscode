# Agent Note: Client Write Sandbox and Queue Serialization

Status: implemented

## Problem
在 AI 工具与工作区文件交互的实现中，暴露出以下架构复杂性与安全隐患：
1. **租约机制过于复杂脆弱**：旧代码中实现了基于 `capability lease` 的并发文件写入租用机制，存在状态回收不全、死锁及清理复杂的缺陷。
2. **缺乏统一写入序列化**：多个并行或链式工具执行文件写入时，缺少全局排队保障，容易引发竞争冒险与写覆盖。
3. **沙箱逃逸隐患**：对工作区路径包含性的校验散落在各工具外层，部分仅基于简单字符串前缀匹配，面对软链接或相对路径时存在逃逸风险。
4. **代码库死资产堆积**：存在废弃的脚手架目录和多余配置。

## Decision
1. **移除 Capability Lease 机制**：
   - 彻底废除基于租约的文件访问控制，简化文件读写生命周期。
2. **建立全局串行写入队列**：
   - 所有文件修改工具（写入、补丁、删除等）统一通过单一写入队列调度执行，强保证多步写操作的原子串行化。
3. **强制收口严格写入沙箱**：
   - 在执行写入前使用 `path.relative` 与真实绝对路径对目标路径进行严格断言，工作区外的写操作一律在门禁阶段拦截并拒绝。
4. **清理死代码与脚手架**：
   - 移除了无用依赖与脚手架文件，同步收窄打包构建配置。

## Alternatives considered
- **保留并调试修复 Capability Lease**：
  - *未采纳原因*：在单一 VS Code 扩展宿主实例中，复杂分布式式租约机制完全是过度设计。串行写入队列在大幅减少代码量的同时，能提供更确定、可推导的并发安全保证。
- **依赖 VS Code 提供的 WorkspaceFS API 自动做沙箱**：
  - *未采纳原因*：底层仍有部分操作涉及 Node 原生 I/O 或工具链调用，在插件逻辑层建立硬性沙箱断言能提供更稳固的深度防御。

## Consequences
- 彻底消除了文件写入竞态冲突和潜在死锁。
- 建立了不可绕过的工作区写沙箱基线。
- 精简了客户端核心运行时代数，提升了可维护性。
