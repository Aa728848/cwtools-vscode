# Agent Note: Release v2.24.0 for Engine-Fact-Driven Performance Diagnostics

Status: implemented

## Problem

自 `v2.23.0`（2026-09-28）以来共 9 个提交、32 个文件、+3826/-11，可归为四组面向用户的改动：

1. **引擎事实驱动校验器 CW279–CW289**（`670b2212`、`1924fa97`、`a4244a1a`、`fbd65f31`）：`v2.23.0` 为 1248 条命令标注了 `## cost` 引擎开销，但**标注只是知识**。引擎对「哪些写法真的掉帧」的反常识行为仍不可见——岗位重排 effect 在循环内同步重跑整星球分配（`EnsurePopJobsAreUpToDate`）、`create_country` 同步联络全银河并重建数据库数组、权重块内 `factor = 0` 不会提前退出、高频块内未加 `?` 的作用域跳转失效时把整个作用域序列化进错误日志。`docs/engine-perf-lint-handoff.md` 将剩余工作分为 A（复杂度细分）/ B（结构反模式）/ C（CW279 宿主扩展）/ D（inline_script 复用提示）四类，本次全部落地。
2. **文档扩充**：新增 `docs/better_stellaris/` 16 篇 Stellaris 4.5 反编译分析与 `docs/stellaris-engine-performance-scan.md` 全量开销清单（trigger 658/892、effect 590/774）。
3. **CI 子模块修复**（`7a35ab08`）：自 `364646df` 起每次 CI 都在 `actions/checkout` 失败，根因是嵌套工作副本提交了未推送的子模块指针。
4. **`log` 开销标注修正**（`1f8132bc`）与**嵌套 inline script goto 定义修复说明**（`74580e48`）。

第 1 组包含 11 条**新增的用户可见诊断码**与一个新的规则指令通道（`## sync_effect`），依据 SemVer 应升级次版本 `2.24.0`。

## Decision

1. **版本号升级（Minor）**：
   将根目录 `package.json` 与 `release/package.json` 的 `version` 统一升级为 `2.24.0`。
2. **更新日志编写**：
   在 `release/CHANGELOG.md` 顶部新增 `## [2.24.0] - 2026-09-30` 区块，按既有中英双语格式分两组：引擎事实驱动的性能反模式检查（CW279-CW289 特性 / CW281 撞名修复 / 开销分类细分与 `log` 修正），以及文档扩充与 CI 子模块修复。
3. **单源文档与门禁**：
   运行 `npm run build:docs` 同步 `release/README.md`，运行 `npm run compile` 与 `npm run check:release -- --skip-compile --skip-test` 验证版本一致性、NLS 完整性、文档单源约束与平台产物存在性。
4. **跨平台通用 VSIX 打包**：
   执行根目录 `package.ps1`，依次发布 win-x64（ReadyToRun）、linux-x64、osx-x64 自包含 F# 语言服务器，重新压缩内置规则包（从子模块 HEAD 读取 commit 与时间戳写入 `stellaris-rules.version.json`），编译 TypeScript 客户端与 Rollup Webview，最终由 `@vscode/vsce` 输出单一通用 `.vsix`。
5. **Git 与 GitHub 发布**：
   提交版本与日志变更，打 `v2.24.0` 标签，推送分支与标签，并通过 GitHub CLI 创建 Release 并挂载 VSIX 产物。

## Alternatives considered

- **升级为补丁版本 `2.23.1`**：不采纳。CW279–CW289 是 11 条**新增的用户可见诊断码**，并新增了 `## sync_effect` 规则指令通道与 `script_eval` / `scope_copy` 两个开销类别，不是既有行为的缺陷修复。
- **把同步副作用的 fact 硬编码在 F# 后端**：不采纳。`add_building` / `create_country` 等 effect 的副作用是随游戏版本变化的内容，硬编码会导致每次版本更新都要改代码发版；已改为 `## sync_effect = pop_jobs | heavy` 规则元数据，后端只做分类与匹配。
- **CW282 / CW283 采用 Warning / Error**：不采纳（已实施的反向决策）。根据实操体验调整梯度，避免强阻断日常编写：CW282 与单层 CW283 降为 Information，仅对两层及以上嵌套循环的 `create_country` 升级为 Warning。CW289 阈值取 20 而非 5，因为十余次模板复用在正常 mod 中很常见。
- **规则子模块变更与扩展发版分离**：不采纳。内置规则包随 VSIX 分发（`release/rules/stellaris-rules.zip`），子模块指针与规则包必须在同一次发版中一起交付，否则用户拿到的校验行为与声明版本不一致。
- **把 CI 子模块修复归入本次更新日志的「修复」段落**：采纳，因其直接影响用户可获得的构建产物，属于用户可见的可靠性变化。

## Consequences

- 发布 `v2.24.0` 通用扩展包，覆盖 Windows / Linux / macOS 自包含运行环境。
- Stellaris 脚本校验新增 11 条引擎事实驱动的性能诊断（CW279–CW289，全部 Information 起、仅嵌套 `create_country` 与 CW281 为 Warning），覆盖高频块高开销命令、MTTH modifier 块、循环内同步副作用、嵌套迭代、权重短路、跨作用域读变量、重复作用域跳转、不安全作用域切换与 `inline_script` 复用。
- 新增 `script_eval` 与 `scope_copy` 开销类别，笼统 `o(n)` 细分为 `script_eval` / `o(n)_galaxy` / `o(n)_owned` / `o(n^2)` / `o(1)` / `o(log n)`；`log` 由 O(n) 更正为 O(1)。
- CI 检出恢复可用：`cwtools-mcp` 指向 `650d119`，固定的是已推送的规则子模块副本。
- 内置规则包与 `cwtools` / `cwtools-stellaris-config` 子模块指针保持一致。
- 已知局限：复杂度等级是实现形态的推断而非基准测试；调用深度 1 之外若有扫描会被漏判为 O(1)（实测该比例约 35%），故 "O(1)" 取保守定义——命令及其直接调用者均无循环。
- 版本号仅由根 `package.json` 与 `release/package.json` 承载，文档与注释不重复数字，遵循既有约定。
