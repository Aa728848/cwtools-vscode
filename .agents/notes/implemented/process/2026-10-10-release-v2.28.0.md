# Agent Note: 发布 v2.28.0

Status: implemented

## Problem

Linux 用户反馈「保存 API 出错」，输出通道只有 `[Eddy] [WARN] [ChatPanel] Error handling webview message 'saveSettings'`。定位后确认为 `saveSettings` 无 try 直写链 + 两个未注册配置键导致整次保存中断，另发现 VS Code 在钥匙串不可用时会静默把 SecretStorage 降级为内存存储，造成「保存成功但 Key 重启即失」的第二类表现。修复详情见 `.agents/notes/implemented/bug-fix/2026-10-10-ai-settings-save-config-write-resilience.md`。

发布时另发现两项**必须先于打标签解决的既有缺陷**：

1. **内置规则包陈旧**：`release/rules/stellaris-rules.zip` 与 `stellaris-rules.version.json` 由 `package.ps1` 生成，但该生成步骤写在 `if (-not $SkipClient)` 分支内。凡是带 `-SkipClient` 的打包（如 `npm run pack:quick`）都**不会**刷新规则包，而 `release/rules/` 是被 git 跟踪的发布产物。本次工作区里的包正是旧指针产物：版本元数据记的是 `f9182443`，仓库实际 pin 的是 `0c6a65a`（「re-anchor cost annotations to the 4.5.2 dump」，1,224 条注解）。若直接沿用 `-SkipClient` 打包，2.28.0 会带着旧规则发布，而 changelog 里写着「子模块提升到重新锚定后的规则」——文案与产物互相矛盾。
2. **发布版 F# 服务端不在版本控制内**：`release/bin/**` 被 `.gitignore` 的 `bin/` 规则覆盖，因此 VSIX 里的三平台自包含服务端**只来自本地构建**，不由任何提交保证。任何一次「在陈旧工作区上打包」都会把旧服务端发出去，且 diff 与 CI 都不会报警。

## Decision

- **版本号**：2.27.0 → 2.28.0（次版本）。依据 SemVer：自 v2.27.0 tag 以来有 5 个提交从未进入任何 changelog，其中 WorkBuddy 离线模型表属于用户可见新特性，故升次版本而非补丁。
- **补齐全量 changelog**：v2.27.0 之后未记录的 5 个提交（PTC 提问与原版读取、设置页草稿保护、WorkBuddy 离线模型表与推理档位、引擎成本锚定、战斗伤害文档）与本次修复一并写入 `[2.28.0]`。
- **不使用 `-SkipServer -SkipClient` 打包**：全量执行 `package.ps1`，确保规则包由**当前 pin 的子模块指针**重新压缩、三平台服务端与客户端 JS 全部重建。这是本次发布最关键的流程判断——跳过步骤省下的两分钟，换来的是一次产物与文案互相矛盾的发布。
- **版本号手工改写而非交由脚本**：`package.ps1 -Version` 用 `JSON.stringify(pkg, null, 4)` 重写整个文件，会把根 `package.json` 的 2 空格缩进整体改成 4 空格，产生 178 行无意义 diff。改为保留脚本对 `release/package.json`（本就是 4 空格）的写入，根文件只定点改版本字段。

## Alternatives considered

- **沿用 `pack:quick`（`-SkipServer -Install`）出包**：否决。它会同时跳过规则包刷新与服务端重建，正是上述两个缺陷的触发路径；本次已经实测出陈旧产物。
- **临时给 `-SkipClient` 补一条规则包刷新**：否决。改 `package.ps1` 的分支结构属于独立的重构，会扩大本次发布变更面；正确修法是让规则包生成脱离 `-SkipClient` 分支，记入后续（见 Consequences）。
- **按补丁号 2.27.1 发布**：否决。WorkBuddy 离线模型表与推理档位是用户可见的新能力，压成补丁号会让 changelog 与实际交付不符。

## Consequences

- **收益**：2.28.0 的规则包与三平台服务端均来自本次工作区的实际代码状态，changelog 描述与 VSIX 内容一致。
- **流程约束（未修复，本次仅规避）**：`package.ps1` 的 4/4b 步（规则包压缩、静态资源拷贝）仍与 `-SkipClient` 绑定。任何后续发布若使用 `-SkipClient`，务必确认 `release/rules/stellaris-rules.version.json` 的 `commit` 等于 `git rev-parse HEAD:submodules/cwtools-stellaris-config`，否则即为陈旧产物。建议的根治方案是把规则包与静态资源步骤拆出 `-SkipClient` 分支，或改为独立开关。
- **未实测项**：VSIX 内 `rules/stellaris-rules.zip` 的实际内容正确性由 `stellaris-rules.version.json` 的 commit 字段核对，未逐条解包比对 1,224 条注解。
- **测试状态**：新增 `chatSettingsSave.test.ts` 2 例（含反向验证：把一行改回直写后必失败，异常类型为生产环境的 `ERROR_UNKNOWN_KEY`）；`typecheck:test`、`lint`（0 error）、`compile`、`check:release` 全通过。
