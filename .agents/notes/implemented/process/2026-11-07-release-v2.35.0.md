# Agent Note: Release v2.35.0 —— 内置 Agent 收敛为 Paradox 单 Agent 并升级 cwtools-mcp 0.2.9

Status: implemented

## Problem

自 `v2.34.1`（2026-11-06）发布以来，主分支合入了单个大体量重构提交 `6846d076`（`refactor(ai,mcp)`），交付面包含两部分互相支撑的变化：

1. **内置 Agent 能力领域与工具面收窄**：`client/extension/ai/` 与 `client/webview/chat/` 已累积至约 12.7 万行 TypeScript，其中大量体积用于通用/混合领域、内置多 Agent 编排（`orchestrator/`、DAG 任务图、Agent Teams 邮箱与 CAS 任务看板、Blackboard）、Shell 命令与进程工具（`run_command`、`manage_process`）及其配套的 OS 命令沙箱（`sandboxRunner`、`sandboxBroker`、`commandPreflight`）与权限审批系统（`permissionRequest`、`autoReviewer`、`permissionPolicy`）。这些能力与外部主流 Agent（DSH / Claude Code / Codex）重叠且存在先天代差，在 VS Code 语言扩展内重复维护整套重型 Harness 带来高昂的维护税与跨平台兼容负担。
2. **MCP 桥接与 `cwtools-mcp` 的语义能力升级**：此前 `tools/generate-mcp-schema.cjs` 已导出 37 个只读 Paradox / Shader 语义工具，但宿主侧 `mcpBridgeServer.ts` 的只读白名单只放行了 25 个；`cwtools-mcp` 0.2.9 同时带来受控领域写入、技能 Resources 与 IDE 现场感知/可视化编辑器联动。若只更新子模块指针而不发扩展版本，VSIX 内的语言服务器、规则包与工具 Schema 无法把这份能力送到终端用户。

上述变化改写了模型可见工具面、`release/package.json` 配置贡献与三语 NLS 词条，属于用户可见的能力下线与新增，必须按可追溯的扩展版本交付。

## Decision

1. **版本定级（Minor `2.35.0`）**：
   依据仓库既有发布惯例——用户可见能力下线以次版本号 + 独立「移除 X / Removal of X」区块发布（参见 [2026-10-19-release-v2.32.0.md](2026-10-19-release-v2.32.0.md) 的 PTC 与 AI Workflow 子系统移除、[2026-10-22-release-v2.33.0.md](2026-10-22-release-v2.33.0.md) 的 WorkBuddy 与 OpenCode Go 线路移除），将根目录 `package.json` 与 `release/package.json` 的 `version` 从 `2.34.1` 升级为 `2.35.0`（2026-11-07）。
2. **更新日志与技术决策归属**：
   在 `release/CHANGELOG.md` 顶部新增 `## [2.35.0] - 2026-11-07` 双语条目，分「内置 Agent 收敛为 Paradox 单 Agent」「MCP 桥接全量对齐与受控领域写入」「文档与一致性」三节。技术设计与取舍归属既有 Owning Note [2026-11-06-streamline-builtin-agent-to-paradox-single-agent.md](../simplification/2026-11-06-streamline-builtin-agent-to-paradox-single-agent.md) 与 `submodules/cwtools-mcp` 仓库提交 `f204f3e`（v0.2.9），本篇只记录发布流程决策，不复制设计细节。
3. **文档事实同步**：
   `README.md`、`ARCHITECTURE.md`、`AGENTS.md` 已在重构提交内同步为单 Agent 现状。发版校对发现 `CONTRIBUTING.md` 中英两段仍宣称 `dispatch_agents`、`query_blackboard`、`merge_results` 是当前多 Agent 工具，并把「命令预检」列为必须保留的护栏，与已交付代码相反；本次在同一发布变更内改写为单 Agent 事实，并指向外部 Agent 经 `cwtools-mcp` 调用语义工具的路径。
4. **单源文档、内置规则包与全平台 VSIX 构建**：
   运行 `npm run build:docs`、`npm run compile`、`npm run typecheck:test`、`npm run test:unit` 与 `npm run check:release -- --skip-compile --skip-test`，随后执行 `package.ps1` 依次编译 win-x64（ReadyToRun）、linux-x64、osx-x64 自包含 F# 语言服务器，按 `submodules/cwtools-stellaris-config` 当前提交重打 `release/rules/stellaris-rules.zip` 与 `.version.json`，并生成通用 VSIX 安装包。
5. **Git 标签与 GitHub Release 交付**：
   将两处版本号、`release/CHANGELOG.md`、本篇发版笔记与 `CONTRIBUTING.md` 事实修正一并提交，创建 `v2.35.0` 标签推送至远端，并通过 `gh release create` 发布挂载 VSIX 的 GitHub Release。

## Alternatives considered

- **升级为破坏性大版本 `3.0.0`**：
  不采纳。扩展的升级路径是市场自动更新，大版本号只会制造破坏性预期，却无法表达本次移除的实际边界——订阅渠道池、`git_ops`、`web_*`、`mcp_call`、媒体工具、全部 Paradox 语义工具、`confirm`/`auto` 文件写入与 Plan 模式门禁均完整保留，移除的是与外部 Agent 重叠的重型 Harness 能力；仓库历史上同类下线（PTC、AI Workflow、WorkBuddy/OpenCode Go 线路）均以次版本交付，保持一致可比对的能力边界。
- **仅更新 `submodules/cwtools-mcp` 指针而不发扩展 Release**：
  不采纳。三平台自包含 `.NET` 服务端、内置规则包与 MCP 工具 Schema 都随 VSIX 分发；不发版则用户既拿不到桥接白名单补齐后的 40 个只读工具与 IDE 感知工具，也看不到被移除工具与设置的真实下线，`release/package.json` 与 NLS 的变更同样无法生效。
- **把 `CONTRIBUTING.md` 的遗留表述留到下一个版本**：
  不采纳。发布提交会固化文档事实，`CONTRIBUTING.md` 属于 release-facing 单源双语文档，让它与交付代码相反会在下游贡献者与 Agent 中制造持续误导。

## Consequences

- 交付 `v2.35.0` 全平台通用 VSIX：内置 Agent 只保留 Paradox 单 Agent 语义辅助、本地化与受保护写入、`git_ops`/`web_*`/`mcp_call`/媒体工具以及 `confirm`/`auto` 写入切换，`client/extension/ai/` 净减超过 1.6 万行，配套 19 个专项旧测试文件一并移除。
- 升级影响：`approvals.reviewer*`、`developer.disableSecuritySandbox`、`policy.preset`、`shell.commandRules`、`orchestrator.agentModels` 等旧配置键在用户 `settings.json` 中保留原值但不再生效；历史话题与 V4 checkpoint 中持久化的 `'general' | 'hybrid'` 领域、`'parallel' | 'specialist'` 调度模式在读取时归一化为 `'paradox'` 与 `'single'`，旧会话不失效。
- 对下游能力约定的影响：`cwtools-mcp` 0.2.9 已推送至 npm，桥接只读白名单与导出 Schema 对齐为 40 个只读工具，受控写入需 `--allow-domain-writes` 显式开启，默认严格只读；后续新增模型可见工具必须同步 `definitions.ts`、`registry.ts`、`agentTools.ts` 与 `npm run generate:mcp-schema`。
- 后续约束：内置 Agent 不再接收新的通用 Harness 能力（Shell、进程、多 Agent 编排）；此类需求应落在 `cwtools-mcp` 或外部 Agent 侧，避免重型 Harness 回流到 VS Code 语言扩展内。
