# Agent Note: Upstream CWTools Refactoring and Submodule Pointer Synchronization

Status: implemented

## Problem
上游 F# 规则与解析引擎内核 `CWTools`（位于 `submodules/cwtools`）是整个插件的领域验证核心，但在长期演进中积攒了多项工程与架构债务：
1. **跨游戏样板代码繁多**：在不同游戏类型的实现中，包含了大量同构的文件遍历、本地化词典装配与规则校验样板代码，缺乏公共抽象。
2. **防御层与日志口径不一**：底层异常捕获、错误日志打印与跨平台路径规范化（Windows 反斜杠与 Unix 斜杠）在不同模块间存在多种处理风格。
3. **测试夹具与根目录文件杂乱**：存在悬挂无效的 `.cwt` 配置文件，部分测试套件在现代构建环境下偶发失败。
4. **主仓同步脱节风险**：若不及时随上游治理平滑推进主仓指针，会导致双方技术债务持续分叉，阻碍主仓调用最新优化特性。

## Decision
1. **上游六阶段系统性治理**：
   - **Phase 1（`55c06638`）**：清理无用死代码与废弃测试夹具。
   - **Phase 2（`c23ee2a4`）**：修复测试 Harness 与 CI 流水线。
   - **Phase 3（`8f1d762f`）**：移除根目录悬挂 cwt 规则文件并确立规则基线。
   - **Phase 4（`c09afcb0`）**：收敛防御层、统一异常日志输出与跨平台路径规范化标准。
   - **Phase 5（`c65b921f`）**：彻底消除跨游戏的同构样板代码与重复数据结构。
   - **Phase 6（`cec56ee1`）**：审查残余清理与最终去重收敛。
2. **主仓分步演进与指针升级**：
   - 随上游节奏分步演进主仓指针（`7a9622ac` -> `9717069f` -> `068b69e5`）。
   - 在主仓同步剔除对上游弃用接口（如旧版 `RulesCache`）的调用，确保 F# 工程编译与 LSP 集成测试在每个升级节点均保持 100% 绿灯。

## Alternatives considered
- **冻结上游子模块指针，仅在主仓层面打补丁**：
  - *未采纳原因*：核心词法与规则引擎问题如果不在上游根本解决，主仓将不得不编写大量侵入性胶水代码进行规避，徒增维护负担；推动上游治理并同步跟进是根本解。
- **上游重构完成后一次性全量提升指针**：
  - *未采纳原因*：跨越 6 个重构阶段的一次性同步风险极大，一旦出现接口破坏极难定位断点；分步推进验证使每一阶段的变动范围受控、可回溯。

## Consequences
- 上游核心库的代码纯净度与健壮性显著改善，跨平台路径判定行为归一。
- 主仓子模块指针无缝更新至最新稳定基线 `cec56ee1`，彻底消除了历史遗留废弃依赖。
